# Silex on .NET 8 vs .NET 10 — 2026-05-30

Silex multi-targets `net8.0` and `net10.0`; `dbbench` multi-targets `net10.0`
(default) and `net8.0`. This runs the identical workload on each runtime to
isolate the framework/JIT/GC difference (same source, same package code paths,
only the TFM changes).

## Setup

- **Host**: macOS, Apple Silicon, 14 cores
- **Threads**: 1, **Dataset**: 1,000,000 entries, 16-byte keys, 100-byte values
- **Seed**: 42 (reproducible); `--benchmarks=fillseq,fillrandom,overwrite,readrandom,readseq`
- Each runtime run 3×; table reports the **best (lowest µs/op)** of the 3.
- Binaries run directly from `bin/Release/<tfm>/dbbench` (no `dotnet run` overhead).
- net10 build uses `System.IO.Hashing` / `Microsoft.Extensions.Caching.Memory`
  `10.0.8`; net8 build uses the `8.0.x` versions.

## Results (best of 3, µs/op — lower is better)

| Benchmark  | .NET 8 | .NET 10 | Δ (net10 vs net8) |
|------------|--------|---------|-------------------|
| fillseq    | 1.154  | 1.149   | ~0% (tie)         |
| fillrandom | 1.097  | 1.127   | −2.7% (net8 edge, within noise) |
| overwrite  | 1.122  | 1.120   | ~0% (tie)         |
| readrandom | 0.555  | 0.511   | **+8.6% faster**  |
| readseq    | 1.704  | 1.572   | **+7.7% faster**  |

(Reads run over the random-fill database, ~63% key coverage — identical between
runtimes, so the relative comparison is fair. found = 632,706 of 1,000,000 in
both.)

## Takeaways

- **Reads improve on .NET 10**: random point-reads ~9% faster and forward scans
  ~8% faster, consistently across runs. The read/iteration paths (merge iterator,
  comparisons, span slicing) benefit most from the newer JIT/GC.
- **Writes are a wash**: fillseq/overwrite are within noise; fillrandom showed a
  tiny net8 edge inside run-to-run variance. The write path is dominated by the
  single writer lock + memtable insert, which the runtime upgrade doesn't move.
- Net: upgrading the target runtime is a free ~8% on the read path here with no
  source changes. Writes are bottlenecked elsewhere (lock/memtable), so they're
  unaffected.

## Reproduce

`dbbench` ships targeting `net10.0` only. To re-run this comparison, temporarily
add `net8.0` to its `<TargetFrameworks>` (Silex already multi-targets both), then:

```sh
dotnet build Silex.DbBench -c Release

BENCH="--benchmarks=fillseq,fillrandom,overwrite,readrandom,readseq --num=1000000 --seed=42"

./Silex.DbBench/bin/Release/net8.0/dbbench  $BENCH
./Silex.DbBench/bin/Release/net10.0/dbbench $BENCH
```
